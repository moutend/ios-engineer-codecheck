# Issue #2: 主要フローの安定化

## 調査と修正

Issue #1 の既存対策を確認した上で、Issue #2 に5件の問題一覧を先に投稿した。

1. 入力変更時の古い検索状態: 非空文字列への編集でも送信済みの検索を無効化する。前後の空白だけの変更は同じクエリとして扱い、検索開始はキーボードの Search 操作に限定する。
2. キャンセル時の状態: キャンセルを無視したサービスが成功を返しても現在の検索を idle に戻す。古いリクエストの成功・失敗は新しい検索を上書きしない。
3. レスポンスの重複: デコード済み items を既存の Repository.ID で重複排除し、最初の項目と順序を維持する。
4. 読み込み失敗時のブックマーク表示: 未読み込みを空一覧と表示しない。再試行に成功すると正常な空一覧に切り替わり、詳細からの追加も有効になる。
5. 一覧・詳細のレイアウト: ViewThatFits で横並びが収まらない場合に縦配置へ切り替える。アクセシビリティ文字サイズでは縦配置を優先し、複数行の高さを確保する。

レイアウトは Apple の [ViewThatFits](https://developer.apple.com/documentation/swiftui/viewthatfits) の仕様に基づく。

## 回帰テスト

既存のテストに加えて以下を検証する。実行方法は [Issue #1 の検証メモ](issue-1.md) と同じ。

- キャンセル後の正常応答、入力編集前の遅延した成功・失敗、結果・エラー表示後の入力編集、古いリクエストの遅延エラー。
- 同一IDの検索結果、不正JSON、items 欠落・null・不正要素。既存のHTTP 403/429/500と特殊文字のクエリも再実行。
- UIでの未検索・検索中・0件・通信失敗・空白入力・再検索。
- 読み込み失敗アラートを閉じても空一覧と誤表示しないこと、再試行、詳細の追加ボタンの無効化と復帰。
- 長い名前・言語・9桁の統計値と最大アクセシビリティ文字サイズでの縦配置、画面幅内への収まり、スクロール後のブックマーク操作。
- 既存のタブ間同期、削除後の詳細維持、再追加、再起動後の追加・削除結果。

Debug の UI テスト専用サービスで `empty` / `failure` / `slow` / `layout` の応答を注入する。`slow` はキャンセル可能な遅延でローディング表示中の編集を確認する。単体テストの非同期競合は引き続き Continuation で制御し、時間待ちに依存しない。読み込み失敗からの復帰は専用のインメモリ保存先で再現する。実ファイル破損時にデータを上書きしないことは既存の単体テストで検証する。
